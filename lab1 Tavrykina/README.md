# Вариант 9 (HSV ↔ XYZ ↔ LAB) — исправленная версия

## Что было не так в исходном коде

1. **`HsvToXyz` / `XyzToHsv` были физически бессмысленными.**
   Исходный код считал что-то вроде
   `X = V·S·cos(H)·0.4124564 + V·(1-S)·0.3575761`.
   Такой формулы в природе не существует: HSV — это не независимая
   физическая модель, а просто цилиндрическая перестановка координат
   RGB-куба (поворот вокруг диагонали куба + пересчёт в цилиндр).
   Единственный корректный путь: **HSV → RGB → (линеаризация) → XYZ**
   и обратно. Старая формула давала неверный цвет почти для всех H,
   кроме H=0, и не была взаимно обратной.

2. **Матрица RGB↔XYZ была жёстко зашита** (константы sRGB/D65:
   `0.4124564, 0.3575761, ...`), хотя по заданию (п.2 доп. требований)
   «жёстких констант для перевода в XYZ и LAB быть не должно», а при
   смене освещения матрицы должны **пересчитываться на лету**. В
   старом коде переключение D65/D50/E меняло только белую точку в
   формуле Lab, а сама матрица RGB→XYZ оставалась той же (D65),
   так что результат для D50/E был неверным.

   **Исправлено:** `ColorMath.BuildRgbToXyzMatrix(Illuminant)` строит
   матрицу заново из хроматичностей основных цветов sRGB и **выбранной
   белой точки**, вручную решая линейную систему 3×3 (метод Крамера) —
   без единой библиотеки. Я проверил это независимо в Python: матрица,
   построенная так для D65, поэлементно совпадает со стандартной
   sRGB-матрицей и даёт эталонные значения Lab для красного
   (L=53.24, a=80.09, b=67.20) — то есть подход математически верен.

3. **Требование 5 (динамические градиенты под ползунками)** не было
   реализовано. Добавлены полоски-градиенты над каждым ползунком,
   показывающие результат при протяжке этой компоненты при текущих
   значениях остальных двух (см. `Form1.RedrawGradients`).
   Примечание: нативный `TrackBar` в WinForms не поддерживает надёжную
   прозрачность фона, поэтому градиент нарисован отдельной полоской
   рядом со слайдером, а не «под» его painting-слоем — так надёжнее
   работает на любой машине, включая ПК преподавателя.

4. **Не было разделения на слои и тестов** (нужно для оценок 8-10).
   Добавлено:
   - `ColorConverter9.Model` — чистая математика (`ColorMath.cs`) и
     `ColorViewModel.cs` (Controller/ViewModel), ни одного упоминания
     `System.Windows.Forms`.
   - `ColorConverter9.App` — WinForms `Form1` (View), которая только
     рисует контролы и вызывает ViewModel.
   - `ColorConverter9.Tests` — MSTest-проект с тестами: сверка
     эталонных Lab-значений для R/G/B/белого/чёрного, инвариант
     «RGB-белый → всегда Lab(100,0,0) при любом освещении», round-trip
     тесты HSV↔XYZ, RGB↔XYZ, LAB↔XYZ, тесты определения выхода за
     гамму.

## CMYK / UCR-GCR

Пункт 3 доп. требований (UCR/GCR) относится к вариантам, где есть
CMYK. Вариант 9 — **HSV ↔ XYZ ↔ LAB**, CMYK в нём не участвует, поэтому
это требование неприменимо.

## Сборка и запуск

Нужен .NET 8 SDK (Windows, для запуска приложения) или любой
Linux/Mac с .NET 8 SDK — для сборки/прогона тестов Model-проекта.

```
dotnet build ColorConverter9.sln
dotnet run --project ColorConverter9.App
dotnet test ColorConverter9.Tests
```

Приложение соберётся в `ColorConverter9.App/bin/Debug/net8.0-windows/ColorConverter9.exe`.
